# [T86] v2.1 docs — correct the run-state CONTRACT, document runs, spend and the one lint gate

milestone: v2.1 · track: docs · depends_on: T80, T82, T83, T84, T85 · provides: `docs/planning/ARCHITECTURE.md` — the authoritative contract — corrected on the run-state source, the state vocabulary and the missing-marker rule; `docs/architecture.md` brought in line; `usage.md` gaining runs, spend and the changed editability rule; `README.md` reflecting the new views.

## Context

Every other v2.1 ticket fixes something the docs currently assert, so the correction **is** the deliverable rather than a tidy-up after it.

**The authoritative file is `docs/planning/ARCHITECTURE.md`, not `docs/architecture.md`.** `CLAUDE.md` names `docs/planning/` as the contract set every lane builds against; `docs/architecture.md` is the derived, user-facing copy. Both carry the wrong claim and both must change, but the planning one is what the code was built from and what a future lane will read.

`docs/planning/ARCHITECTURE.md` §"Factory run-state directory (read-only)" states:

> Fallback probe order: `<root>/.factory/run-state/`, then `<root>/docs/planning/.run-state/`. Per-ticket state via marker file or subdirectory… **Absence of the run-state dir → all tickets `RunState.unknown`. Present dir but missing marker → `RunState.todo`.** … v2's editing gate uses `RunState == todo` (or `unknown`) as the only editable predicate.

Measured against the factory: it writes no such directory. It writes `.factory/run-state.json`, and its vocabulary is the nine values of `FAC_STATES` with no `in_flight` among them. The string `run-state.json` does not appear anywhere in the authoritative file. **The code faithfully implements this contract; the contract is wrong about the factory** — which is why no test caught it, and why fixing only the code would leave the next lane to rebuild the same thing from the same source.

The sentence *"present dir but missing marker → `RunState.todo`"* is a second hole, distinct from the one T80 was written for. `todo` is **mutable**, so even in a project where the directory form does exist, a ticket the run-state does not list is editable. T80 changes that to `absent`; this ticket is where the contract catches up — **a contract amendment, not a description of code.** Say so explicitly, or the next reader will take the doc as having always meant it.

## Staged approach

1. `docs/planning/ARCHITECTURE.md`: rewrite §"Factory run-state directory (read-only)" as §"Factory run-state source (read-only)". The console resolves a **source** — `.factory/run-state.json` first, then the legacy marker directories — and reports which it used. Give the factory's real vocabulary (`todo`, `in_progress`, `ready`, `in_part`, `in_submilestone`, `merged`, `flagged`, `failed`, `needs_human`) plus the console-side `unknown` (no source) and `absent` (source exists, ticket not listed). State the resolution rules: **no source → `unknown` (mutable); source present, ticket unlisted → `absent` (NOT mutable)**. The second replaces "missing marker → `todo`" and is a deliberate behaviour change — mark it inline, quoting the text it replaces.
2. Keep an explicit correction note in that section recording that the previous text described a directory the factory does not write, and that the code matched the text. A corrected document that reads as though it was always right teaches nothing about how the defect happened.
3. `docs/planning/ARCHITECTURE.md`: add the read-only factory artefacts the console now consumes — ledger, results, receipts, last-stop — with the rule governing all of them: **`.factory/` is gitignored, so every source is optional and a missing one renders as missing, never as zero or empty.**
4. Check §"v3 — Hosted multi-project control plane" for anything this milestone invalidates. It is a separate, still-reserved milestone — **do not renumber it and do not fold v2.1 into it** — but if it assumes the run-state directory or the five-state vocabulary, that assumption is now wrong and correcting it belongs here.
5. `docs/architecture.md`: apply the same corrections to the derived copy so the two cannot disagree; where it summarises, it must summarise the corrected contract.
6. `docs/usage.md`: add `/runs` and `/spend` — what each shows, and what the no-run-data state means to someone reading a fresh clone — including the attributed-cost rule, since a per-ticket column that over-sums the total looks like a bug until explained.
7. `docs/usage.md`: update the editing section for T80. `todo` and no-run-state-source stay editable; a ticket absent from a run-state that exists is refused, and the message names the file consulted. Give the hand-added-ticket workflow as the concrete case.
8. `docs/contributing.md`: `make lint` runs `pre-commit run --all-files` and is the same gate CI runs; hooks are added to `.pre-commit-config.yaml` only. State why — the Makefile used to enumerate its own set and the two drifted in **both** directions.
9. `README.md`: extend the capability summary to include run and spend visibility, one line each, linking to `usage.md`.
10. `docs/planning/ROADMAP.md`: add the v2.1 section listing T78–T86. Leave its v3 "Mission control" section untouched.
