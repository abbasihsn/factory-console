# [T86] v2.1 docs — correct the run-state CONTRACT, document runs, spend and the one lint gate

milestone: v2.1 · track: docs · depends_on: T80, T82, T83, T84, T85 · provides: `docs/planning/ARCHITECTURE.md` — the authoritative contract — corrected on the run-state source, the state vocabulary and the missing-marker rule; `docs/architecture.md` brought in line; `usage.md` gaining runs, spend and the changed editability rule; `README.md` reflecting the new views.

## Context

Every other v2.1 ticket fixes something the docs currently assert, so the correction **is** the deliverable rather than a tidy-up after it.

**The authoritative file is `docs/planning/ARCHITECTURE.md`, not `docs/architecture.md`.** `CLAUDE.md` names `docs/planning/` as the contract set every lane builds against; `docs/architecture.md` is the derived, user-facing copy. Both carry the wrong claim and both must change, but the planning one is what the code was built from and what a future lane will read.

`docs/planning/ARCHITECTURE.md` §"Factory run-state directory (read-only)" states:

> Fallback probe order: `<root>/.factory/run-state/`, then `<root>/docs/planning/.run-state/`. Per-ticket state via marker file or subdirectory… **Absence of the run-state dir → all tickets `RunState.unknown`. Present dir but missing marker → `RunState.todo`.** … v2's editing gate uses `RunState == todo` (or `unknown`) as the only editable predicate.

Measured against the factory: it writes no such directory. It writes `.factory/run-state.json`, and its vocabulary is the nine values of `FAC_STATES` with no `in_flight` among them. The string `run-state.json` does not appear anywhere in the authoritative file. **The code faithfully implements this contract; the contract is wrong about the factory** — which is why no test caught it, and why fixing only the code would leave the next lane to rebuild the same thing from the same source.

The sentence *"present dir but missing marker → `RunState.todo`"* is a second hole, distinct from the one T80 was written for. `todo` is **mutable**, so even in a project where the directory form does exist, a ticket the run-state does not list is editable. T80 changes that to `absent`; this ticket is where the contract catches up — **a contract amendment, not a description of code.** Say so explicitly, or the next reader will take the doc as having always meant it.

## Staged approach

1. `docs/planning/ARCHITECTURE.md`: rewrite §"Factory run-state directory (read-only)" as §"Factory run-state source (read-only)". The console resolves a **source** — `.factory/run-state.json` first, then the legacy marker directories — and reports which it used. Give the factory's real vocabulary (`todo`, `in_progress`, `ready`, `in_part`, `in_submilestone`, `merged`, `flagged`, `failed`, `needs_human`) plus the console-side `unknown` (no source), `absent` (source exists, ticket not listed) and `unreadable` (source exists and could not be read). State the resolution rules, which are **four-way** and not two — T80's 2026-08-01 amendment split the middle case and its 2026-08-02 amendment 2 split off a fourth, so a contract written from the original two-way sentence would contradict the merged code:

   - **no source at all → `unknown` (mutable)**;
   - **a resolved but VACUOUS source → `unknown` (mutable)** — a marker directory holding no marker for any ticket, or a `run-state.json` whose `tickets` object parsed and is empty. A source that names nobody exercises no authority over anybody, and answering `absent` here would turn an empty-but-valid run-state into a project-wide read-only lockout;
   - **a POPULATED source that does not list this ticket → `absent` (not editable — but still DELETABLE, see step 7)**;
   - **a source that IS there and could not be READ → `unreadable` (refused for BOTH edit and delete)** — EACCES and friends, or a `run-state.json` whose bytes could not be read at all. The 409 names the source path, so an operator reads it as a permissions problem rather than as "this ticket is not tracked".

   State that a **vanished** source resolves `unknown` (nothing is there to hide a marker) while an **unreadable** one resolves `unreadable`, and that the two must not be folded together: the first three cases are "I looked and there is nothing to find", the fourth is "I could not look", and granting a write because the check could not run is the fail-open T80's amendment 2 exists to close. Do **not** write "an unreadable source resolves `unknown`" — that was this ticket's own pre-amendment-2 instruction and it is now the opposite of the merged code. The `absent` rule replaces "missing marker → `todo`" and is a deliberate behaviour change — mark it inline, quoting the text it replaces.
2. Keep an explicit correction note in that section recording that the previous text described a directory the factory does not write, and that the code matched the text. A corrected document that reads as though it was always right teaches nothing about how the defect happened.
3. `docs/planning/ARCHITECTURE.md`: add the read-only factory artefacts the console now consumes — ledger, results, receipts, last-stop — with the rule governing all of them: **`.factory/` is gitignored, so every source is optional and a missing one renders as missing, never as zero or empty.**
4. Check §"v3 — Hosted multi-project control plane" for anything this milestone invalidates. It is a separate, still-reserved milestone — **do not renumber it and do not fold v2.1 into it** — but if it assumes the run-state directory or the five-state vocabulary, that assumption is now wrong and correcting it belongs here.
5. `docs/architecture.md`: apply the same corrections to the derived copy so the two cannot disagree; where it summarises, it must summarise the corrected contract.
6. `docs/usage.md`: add `/runs` and `/spend` — what each shows, and what the no-run-data state means to someone reading a fresh clone — including the attributed-cost rule, since a per-ticket column that over-sums the total looks like a bug until explained.
7. `docs/usage.md`: update the editing section for T80. `todo`, no run-state source, and a resolved-but-vacuous source all stay editable; a ticket a POPULATED run-state does not list is refused for **editing**, and the message names the file consulted. **Delete is deliberately wider than edit** and must be documented as such: `ensure_deletable` permits `absent`, because `create_ticket` is ungated and a ticket the console just minted is `absent` in any project with a populated source — refusing the delete too would leave a mistyped new ticket unrecoverable through the UI that created it. Give the hand-added-ticket workflow as the concrete case, and note that such a ticket can be deleted but not edited until the factory seeds it. **The widening stops at `absent`**: a source that is there and cannot be READ resolves `unreadable` and refuses BOTH writes, so document it as its own case with its own fix (correct the source's permissions), never as a lifecycle state a lane put the ticket in. Note the consequence a reader will otherwise hit blind: in such a project even a freshly created ticket can be neither edited nor deleted until the source is readable again.
8. `docs/contributing.md`: `make lint` runs `pre-commit run --all-files` and is the same gate CI runs; hooks are added to `.pre-commit-config.yaml` only. State why — the Makefile used to enumerate its own set and the two drifted in **both** directions.
9. `README.md`: extend the capability summary to include run and spend visibility, one line each, linking to `usage.md`.
10. `docs/planning/ROADMAP.md`: add the v2.1 section listing T78–T86. Leave its v3 "Mission control" section untouched.

## Interface & data

Prose is the DELIVERABLE; see the scope amendment above for the code that also landed. Terms fixed here and used consistently in every file: **run-state source** (the resolved file or directory), **`unknown`** (no source, a source that vanished, a resolved but VACUOUS one, or one whose bytes were read and could not be understood — mutable), **vacuous source** (a resolved source that lists no ticket at all: a marker directory with no marker, or `run-state.json` with an empty `tickets` object), **`absent`** (a POPULATED source exists and does not list this ticket — not editable, but still deletable), **`unreadable`** (a source that EXISTS and whose bytes or entries could not be read at all — refused for both edit and delete; distinct from `unknown` because "I could not look" is not "I looked and there is nothing to find"), **attributed cost** (a multi-ticket lane charged in full to each id).
