# [T130] v3.0 user docs + README screenshots refresh

milestone: v3.0 · track: docs · depends_on: T129, T34, T54, T77, T86, T94 · provides: the screenshot pipeline captures the multi-project console, and README + `docs/usage.md` describe the registry, the switcher and the named conditions — so the user-facing docs match what the console now does.

## Context

Every milestone here has ended with a docs + screenshots refresh, and **v2.2's T94 exists precisely
because one did not**: user-facing docs kept describing a contract the code had left behind.

v3.0 changes the FIRST thing a new user meets — the console is no longer about the directory you
launched it in — so `docs/usage.md`'s "What you'll see" and the README gallery are wrong the moment
the switcher lands. This ticket closes the milestone by making them right.

It follows T129, which amends the *planning* contracts; this one is the *user-facing* half, and the
two are separated so a reviewer of either is reading one audience's document at a time.

## Staged approach

1. `frontend/tests/e2e/screenshots.spec.ts`: add captures against a two-project console (via T120's
   dedicated-console helper, as T127 does) — the TopBar with the switcher open, and the `/projects`
   management page — each gated on its own web-first visibility assertion before the shot, matching
   the file's existing discipline. `scripts/copy-screenshots.mjs` needs no change: it copies every
   `*.png`.
2. Regenerate and commit the PNGs: `pnpm --dir frontend screenshots`, which runs the grep'd spec and
   copies into `docs/screenshots/`.
3. `docs/usage.md`: a new "### Projects" subsection under "What you'll see" covering registering a
   project by path, switching, the named refusals, removal (console state only, never files), and
   what a moved path / a non-project path / an unreadable path / no `.factory/` each mean. Plus:
   - a note that `factory-console PATH` still works exactly as before and simply selects that project
     for the session;
   - the registry's location (`~/.factory-console/console.db`) and `FACTORY_CONSOLE_DB_PATH` under
     "Environment" — reconciled with the entries T104, T119 and T128 already added, so the file ends
     with ONE coherent account rather than four accreted ones;
   - that `serve` and remote access are v3.1, so nobody reads multi-project as multi-user.
4. `README.md`: add the two new screenshots to the gallery and refresh the Status/Quickstart lines
   that still describe a single-project viewer.
5. **Re-read the changed prose against the shipped behaviour before committing** — the T94 failure
   mode is docs that were true when written.
